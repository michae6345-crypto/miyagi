## Summary: top 5 area-E risks

1. **Correct learners get "Not yet", and the coach then tells them to change working code (E14 to E17, P0).** Run checks match the model's guessed output exactly (random numbers, `input()`, floats). "No errors" reads old tracebacks still on screen. Lesson-mode checks are token-exact, so typing your own name fails. The coach has no "your code is fine" answer. This is the Khanmigo failure.
2. **Continue loses progress (E03, P0; E01, E29).** Home's Continue on a lesson the learner ended, or one a newer lesson replaced, restarts at step 1 and moves their files into `.miyagi-previous/`. Since today's fresh-start change, Continue is the only way back. The built app also forgets every renderer setting on each relaunch (E01), and the hero PINN lesson's folder is wiped by app updates (E29).
3. **Spinners with no way out (E02, E09, P0).** "Checking" has no timeout, heartbeat or wake handling. A build that stalls or fails after the 8 s placeholder step leaves the learner on a step with no checks that can never pass.
4. **Lessons may fail to build through miyagi-cloud (E08, P0 if the logs show it).** The proxy cuts every Claude reply to 4096 tokens, thinking included; the builder asks for 32000 and treats a cut-off reply as a failure. Published build timings used direct keys. One grep of an engine log answers it.
5. **First run on a real student's Mac (E28, E06, E30, E31, E38).** A school filter that blocks api.anthropic.com makes the engine think it is offline, so Check waits for a network it doesn't need. Each ad-hoc-signed update loses the permissions. The first suggested lesson is effectively random and usually needs tools a fresh Mac lacks. Declining Accessibility locks Home. Whether Gatekeeper lets the bundled Python run after Open Anyway is unknown until Test 1.

Grading also has a false-pass side (E18 to E23: one judge call overrides failures, old output passes a wrong run, commented-out code passes). It hurts learning more than trust at launch, so it is P1.

## Test 1 script: miyagi on a fresh Mac (for Michael)

Builds on `docs/CLEAN-TEST.md` (engine branch), which stays the per-release check. Test 1 goes further: it finds what a brand-new learner hits from download to a passed step, times each part, and probes rows E01 to E41.

**Goal:** on a Mac that has never seen miyagi, Python, the Command Line Tools, Homebrew or VS Code, reach a passed step in a free cached lesson with no Terminal and no key, and record everything that got in the way.

### Setup (once)
1. **Use a macOS VM, not a new user account.** UTM (free) or Tart on Apple silicon, macOS 15, and macOS 26 if you can (27.3 beta too if it is out, for E07). Install from Apple's IPSW, make one admin user, skip the Apple ID. Check it is clean: `xcode-select -p` must fail, and `ls /opt/homebrew /Applications` shows no Homebrew and no VS Code. Don't run `python3` or `git` (they pop the developer-tools dialog). Take a snapshot called "clean"; every variant starts from it. A new user on your own Mac shares Homebrew, the developer tools and `/Applications`, so `CLEAN-TEST.md` Option A can't test the Python or VS Code cases.
2. Record from the host (QuickTime on the host, or a phone), so no recorder inside the VM asks for permissions of its own.
3. Write down: miyagi version and engine commit (About miyagi), macOS version, chip, VM or real Mac, network (home, school, hotspot), and how long miyagi-cloud has been idle (20+ minutes is best, for E40).
4. Keep a timing sheet: one row per step, wall-clock start and end.

### R0: fresh Mac, admin, online, allow everything (about 30 minutes)
1. **Download** from the real download page, as a learner would. Record the time and that the file is about 126 MB. Fail: the Intel note shows on Apple silicon, or the link 404s.
2. **Open the DMG and drag miyagi to Applications.** Record mount and copy time.
3. **First open and Gatekeeper.** Double-click miyagi. Screenshot the block. Done, then System Settings > Privacy & Security > Open Anyway > password > Open Anyway. Count password prompts. **Watch for E38:** any second dialog naming `python3`, `python3.12` or a `.so`, or the pill later saying "miyagi couldn't start". Pass: one block, one Open Anyway.
4. **Intro and sign-in.** Choose Continue without an account (Google is V8). Note any age question.
5. **Engine.** Note when the pill reaches Running (pass under 20 s; fail over 60 s, the start timeout; on failure press Copy details and paste it into the notes). Then "Setting up access for this Mac" turns green: time it. If it fails, press Try again once and time that (a pass on the second try means a cold cloud, E40).
6. **Screen Recording.** Allow, switch miyagi on, relaunch. Pass: miyagi comes back on the same step. Record dialogs and password prompts, and whether macOS asked for the relaunch itself.
7. **Accessibility.** Open System Settings, switch on, return. Pass: green within 2 to 3 s with no relaunch.
8. **VS Code (not installed).** The row should say "VS Code isn't on this Mac yet". Press Get VS Code and download it. **First open VS Code from Downloads** and note what the row says (E32). - A renamed step file is not found and nothing asks "did you rename it?" (`server/orchestrator/workspace.py:60-80`).
- A 10th VS Code window gets no companion port (`vscode-ext/extension.js:740-762`); conda `base` from `.zshrc` may override the lesson `.venv`.
- Package checks don't pass `--only-binary`, so a package with no wheel builds from source and may pop the developer-tools dialog.
- Doc nit: `SHIP.md` says quit with ⌥Q; the shortcut is ⌃⌥Q (`main/index.ts:487-489`).
- Some unfinished lessons can never be continued from Home, because `recent.json` keeps no graph and the lesson isn't cached (`server/sessions/store.py:165-170`, `renderer/src/features/library/homeModel.ts:62`). Fold into the E03 fix.

## Notes: how grading works (engine `integration/live`)

- A model writes each step's checks when the lesson is built. Every check is a case-sensitive Python regex, run against one of: on-device OCR of the screen scoped to an app (`server/checks/screen.py:54-125`), VS Code's live buffer through the companion (`server/orchestrator/editor_text.py:131-157`), the file on disk (`server/checks/evaluator.py:161-184`), a run's output, or notebook cells. Types: `screen_contains`, `screen_absent`, metric checks, and optional precision checks (`server/lesson/schema.py:25-28`).
- "Just teach me" lessons also get token-exact regexes for each function's return and each top-level assignment (`server/lesson/coverage.py:220-330`) and an exact-line check on the run's last expected line (`server/lesson/textlesson.py:782-791`).
- A step passes when all checks pass, or all precision checks pass, unless a failing "absent" check vetoes it (`server/checks/evaluator.py:870-894`, `server/orchestrator/session.py:4168-4176`). Lesson mode adds a required run of the step's command and, for `.py` files, a code gate (compiles, contains every call, def name, kwarg name and short dict string; `server/orchestrator/code_gate.py`).
- A Haiku judge runs in the background (passes pending checks at confidence 0.8 or more, or offers "Looks done?" on failing ones) and on Check (passes the step at 0.6 or more) (`server/coach/judge.py`). Offline, the judge only confirms machine passes (`judge.py:280-289`).
- Grading re-runs on every changed screen frame (about once a second), save, VS Code dirty or save event, run end and Check. Per-step state resets cleanly between steps (`server/orchestrator/session.py:656-725`); only what is still on screen (terminal scrollback) carries over, which is the root of E15 and E19.
- Offline run: `server/checks/tests/test_evaluator.py` passes 52 of 52 on Windows with no network. A probe script called the pure check functions with hand-made inputs to confirm E14 to E16, E19 to E21 and E24 (no model, no keys). Coach and orchestrator tests were not run (they need the `anthropic` SDK or the full engine).
- Missing tests: stale scrollback, intended "Error:" output, random or `input()` output, commented-out code, the learner's own names, call versus def, a Terminal.app run, Confirm versus the code gate.
- There is no `docs/ROADMAP.md` on `integration/live` or `michael/v2-integration` any more, so ROADMAP 1.8 could not be read; E14 to E25 are the concrete list for it.

### Permission prompts
- No maker publishes a macOS Screen Recording or Accessibility grant rate (Rewind, Loom, Raycast, CleanShot, Screen Studio and others searched, Nov 21, 2026). The register says "unknown, measure it" (E04) instead of guessing.
- Closest proxies, all mobile: iOS App Tracking Transparency opt-in about 35% ([Adjust](https://www.adjust.com/blog/att-opt-in-rates-2025), 2025, vendor data) to about 40% of users shown the prompt ([AppsFlyer](https://www.appsflyer.com/company/newsroom/pr/post-att-growth-2/), Apr 2025). macOS is likely worse, because the learner leaves the app for System Settings and often has to relaunch.
- Moving sign-up later raised Duolingo's daily users about 20% ([First Round Review](https://review.firstround.com/the-tenets-of-a-b-testing-from-duolingos-master-growth-hacker), Jul 17, 2017, company self-report). "Continue without an account" should stay one click.
- Mechanics that cause drop-off: the monthly Screen Recording re-prompt on macOS 15 and later (E05), lost grants on ad-hoc-signed updates (E06, C02), and the macOS 27.3 Accessibility split (E07). Whether Screen Recording still needs a relaunch after granting on macOS 15 and 26 is undocumented: test it in Test 1.
