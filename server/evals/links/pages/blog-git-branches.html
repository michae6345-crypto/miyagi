Git branches: a hands-on walkthrough

Posted on March 3, 2026 by Sam Rivera

Contents

  1. Set up a practice repository
  2. Make a branch
  3. Merge it back

Branches are cheap in Git, and the fastest way to stop being scared of them is to make a few in a throwaway repository. Everything here happens in a fresh folder, so nothing you do can hurt a real project.

Set up a practice repository

Make a repository with one commit on the main branch:

git init
git switch -c main
git add notes.txt
git commit -m "First notes"

(Put a line or two of text in notes.txt before the git add.)

Make a branch and work on it

Create a branch called idea and switch to it in one command:

git switch -c idea

Add a line to notes.txt, then commit on the branch:

git commit -am "Try an idea"
git log --oneline --graph --all

The graph shows idea one commit ahead of main.

Merge it back

Go back to main and bring the idea in:

git switch main
git merge idea

Because main had not moved, Git just slides main forward: a fast-forward merge. Delete the branch once it is merged:

git branch -d idea

That's the whole loop: branch, commit, switch back, merge, delete. Next post: what happens when both branches change the same line.
