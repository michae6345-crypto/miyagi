12. Virtual Environments and Packages¶

Last updated on Nov 23, 2026

12.1. Introduction¶

Python programs often use packages that are not part of the standard library. Sometimes a program needs one particular version of a package, and another program on the same computer needs a different one. Installing both into one shared place cannot satisfy both programs at the same time.

The answer is a virtual environment: a self-contained folder that holds its own Python and its own set of installed packages. Each project can have one, and what you install into one never touches the others.

12.2. Creating Virtual Environments¶

The module used to create and manage virtual environments is called venv. To create one, choose a folder for it and run the venv module as a script with the folder's name:

python3 -m venv tutorial-env

This makes the tutorial-env folder if it does not exist, and puts a copy of the interpreter and some supporting files inside it.

Once it exists, activate it. On macOS and Linux, run:

source tutorial-env/bin/activate

Activating changes your shell prompt to show which environment you are using, and makes python run the environment's interpreter:

$ python
Python 3.13.0 (main, Oct  7 2026, 10:12:31)
$ deactivate

12.3. Managing Packages with pip¶

You install, upgrade and remove packages with a program called pip. Inside an active environment, install the latest version of a package by naming it:

(tutorial-env) $ python -m pip install requests
Collecting requests
Successfully installed requests-2.32.3

python -m pip show requests prints what it knows about one package, and python -m pip list lists every package in the environment:

python -m pip list

Write the installed packages to a file so someone else can install the same ones:

python -m pip freeze > requirements.txt

Then anyone can recreate the environment's packages from that file:

python -m pip install -r requirements.txt
