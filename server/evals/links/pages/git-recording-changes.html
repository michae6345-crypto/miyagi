2.2 Git Basics - Recording Changes to the Repository

Recording Changes to the Repository

You have a Git repository on your computer and a folder of files to work on. Now you make changes and commit snapshots of those changes each time the project reaches a state you want to keep. Every file in the folder is either tracked (Git knows about it) or untracked (everything else).

Starting a repository

In the folder of a project that is not under version control yet, turn it into a Git repository:

$ git init
Initialized empty Git repository in /Users/you/my_project/.git/

Checking the Status of Your Files

The main tool for seeing which files are in which state is git status. Create a README file with one line of text, then ask Git what it sees:

$ echo 'My Project' > README
$ git status
On branch master
Untracked files:
  (use "git add <file>..." to include in what will be committed)
    README

Tracking New Files

To begin tracking a new file, use git add. The file is now staged: it will go into the next commit.

$ git add README

Committing Your Changes

When the staging area holds what you want, commit it with a message that says what changed:

$ git commit -m "Add a README"
[master (root-commit) 463dc4f] Add a README
 1 file changed, 1 insertion(+)
 create mode 100644 README

Viewing the Commit History

After a few commits, look back at what happened, one line per commit:

$ git log --oneline
463dc4f Add a README
prev | next
