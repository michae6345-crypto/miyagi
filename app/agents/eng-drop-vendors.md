# eng-drop-vendors (E-vendors: drop the scraping vendor + Tiger)

**Status:** fix round 1 done, pushed, not merged (no merge gate: `config.status` is on-contract today, checked with `Hub(strict=True)`) · **Branch:** `claude/eng-drop-vendors` (from `origin/claude/eng-cloud-client`) · **Engine only** (no app files, no port)

## Goal
A downloaded miyagi never asks for a scraping-vendor key or a Tiger Data URL, and the engine runs (and imports) with neither key and without psycopg. DISTRIBUTION-PLAN section 6: "Stop asking for the scraping vendor and Tiger: `config.py` `KEY_ENV`, `psycopg` out of `pyproject.toml`; full code removal later (ROADMAP 3.6)". Tiger's job (the learning-event and run-metric memory) moves to a local SQLite file under the engine data dir. Plus BUILD-PLAN E4's `FINDER_GEMINI_FALLBACK=0` in `finder/core.py`.

## What changed (server/)
- `config.py`
  - `KEY_ENV` kept the vendor key and `tigerUrl` (fix round 1; the vendor key was removed later, see below): `config.status` is built from `KEY_ENV` in `orchestrator/main.py` and `ConfigStatus` still requires both, so dropping them broke every `config.status` (a hub warning, and under `ORCH_STRICT=1` the `config.keys` handler raised and Settings > Test timed out). `RETIRED_KEYS` (both names): `set_app_keys` skips them, so an app value is never stored or exported to `os.environ`; `apply_keys` only restores or pops the `.env` value.
  - `config.status.tigerUrl` is always `missing` (`key_source`), since the writer no longer reads `TIGER_DATABASE_URL`. The round-0 `ENV_ONLY_KEYS` is gone (KEY_ENV covers it).
  - `safe_env()` still strips `TIGER_*` (and names `TIGER_DATABASE_URL` explicitly).
- `pyproject.toml`: `psycopg[binary]` removed from the engine dependencies; new dev-only extra `tiger = ["psycopg[binary]>=3.2"]` (fix round 1).
- `checks/tiger.py`: same module name and API (`record_event`, `record_metric`, `record_run`, `get_writer`, `TigerWriter`, `replay_spool`, `spool_status`, `stats`, `_redact`), so `orchestrator.modules`, `orchestrator.tiger_runs` and `checks.stats_web` work unchanged.
  - `TigerWriter()` (what the engine uses) writes to the **local store** `metrics_db_path()`: `$MIYAGI_METRICS_DB`, else `<engine data dir>/metrics.sqlite`, the data dir being `$MIYAGI_STATE_DIR` or `~/miyagi/state` (same folder as `server.sessions.store`). Tables `learning_events`, `training_metrics`, `runs` with the contract's columns (`shared/contracts/tiger-schema.sql`), times as unix seconds (UTC), indexes on (lesson_id, time) and (run_id, time), `runs` upserted with the same merge rules. WAL journal, file created `0600` (a `question` event can hold the learner's text). NaN metric values are stored as NULL. Odd values (a list in `tail`) are stored as JSON text, so one bad row cannot poison a batch or the spool.
  - The spool stays as the fallback: if the store can't be opened or written, batches go to `~/.miyagi/tiger-spool` (`$TUT_SPOOL_DIR`) and the writer retries every 30 s, then loads the whole spool, `tut run`'s files included, into the store. One warning per outage. **First start on a Mac that already has a spool:** it is loaded into the store once, in the writer thread (never the engine loop).
  - TIGER_DATABASE_URL is no longer read by the writer (the env-following `_sync_dsn` is gone). The psycopg path remains only for an explicit `TigerWriter(dsn=...)` (tests, dev tools) and `python -m server.checks.tiger --tiger`.
  - `stats(conn)` also takes a local store connection (row totals, rows/s, latency of the two panel reads on raw rows). `local_summary()` and `open_local()` are new.
  - Retention (fix round 1): `prune_local()` runs once per store connect, after the spool load, and deletes `training_metrics`, `learning_events` and `runs` rows older than `$MIYAGI_METRICS_RETENTION_DAYS` (default 90, `0` keeps everything), so `metrics.sqlite` no longer grows without limit. A failed prune is logged at INFO and never takes the writer offline.
  - CLI: `python -m server.checks.tiger --ping` shows the local store path, row counts, newest row and spool backlog; `--flush-spool` loads the spool into it; `--tiger` keeps the old Tiger checks.
- `screen/metrics.py`: its own Tiger writer (screen OCR metrics) is a no-op when psycopg is not installed, even with `TIGER_DATABASE_URL` in `.env` (before: a retry loop on a missing driver). Its "not persisted" log is INFO now.
- `finder/core.py`: Gemini scoring fallback is `FINDER_GEMINI_FALLBACK=0` by default (env.py already) and now also never runs in miyagi cloud mode (`server.config.mode("gemini") == "cloud"`: the cloud's Gemini is video only). 

**Update (the scraping-vendor removal lane): the vendor was removed entirely.** Its finder module is deleted; `finder`, `lesson/transcript.py` and `preflight` use plain HTTP and DuckDuckGo, `coach/web.py` searches DuckDuckGo's HTML endpoint and reads pages with a plain GET, and the vendor key is gone from `KEY_ENV`, `config.status`, `config.keys` and the app's Settings. Older app builds that still send the name are ignored (unknown `config.keys` names are never read).
